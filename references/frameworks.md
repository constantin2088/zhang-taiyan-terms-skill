# 可填写工作表

## 第1步
摘录待解释词及完整上下文，登记作者、时间、文本类型和版本，不从字面立即译成现代概念。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 第2步
列当时用例与对照用例，记录语境差异和后世注释的归属；无原文的例子标转述。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 第3步
区分字形、语音、词义和学科分类，不以字形相近证明概念相同。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 第4步
为每种解释列范围、反例和需要的材料，检验现代译名是否缩窄或夸大原义。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 第5步
比较直译、保留旧词加注和功能释义，说明读者、用途与损失；必要时保留多义。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 第6步
输出词义沿革卡和暂定译注，保留版本差异及待查项，不能把解释表当已完成校勘。

填写：输入及日期｜所用证据｜判断及替代解释｜未知项｜负责人或后续检索｜重审条件。

## 证据和行动校验
关键条目至少填写一个来源定位（source）或下一步核验（next_check）。不将表格通过当作论证真实。可以用 `python scripts/validate_packet.py packet.json` 检查结构，工具不访问网络、不评判观点或代替专业审查。

## 确定性辅助工具

来源谱系去重：多次转载不增加独立来源。

输入例子见 [tool-input.json](../examples/tool-input.json)。
```sh
python scripts/check_provenance.py examples/tool-input.json
```
工具只读取指定本地 JSON，不联网、不更改文件、不执行输入中的指令。填写者仍须复核事实和适用条件。
